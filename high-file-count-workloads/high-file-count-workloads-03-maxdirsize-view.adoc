= maxdir-size 및 현재 디렉토리 크기 보기
:allow-uri-read: 
:icons: font
:imagesdir: ../media/high-file-count-workloads/


[role="lead"]
볼륨  `maxdir-size`필드는 볼륨 내 각 디렉터리에 대해 허용된 최대 용량입니다. 개별 디렉터리를 측정하려면 볼륨에서 사용되는 데이터가 아닌 해당 디렉터리 오브젝트를 검사해야 합니다.



[[view-the-configured-cap]]
== 구성된 캡 보기

[listing]
----
set -privilege advanced
volume show -vserver <svm> -volume <volume> -fields maxdir-size
----
이 수치는 특정 디렉토리의 크기가 아니라 디렉토리별 제한 용량을 나타냅니다.



[[view-the-directory-file-from-an-nfs-client]]
== NFS 클라이언트에서 디렉토리 파일 보기

ONTAP 명령 중에는 개별 디렉토리의 크기를 직접 보고하는 명령이 없으므로 클라이언트 또는 외부 툴을 통해 값을 쿼리해야 합니다. 정확한 디렉토리 오브젝트 크기가 필요한 경우 NFS 클라이언트가 클라이언트 측에서 권장되는 방법입니다.

GNU/Linux 클라이언트에서 마운트된 NFS 경로에 대해  `stat` 을 사용하거나 디렉토리 오브젝트 자체에 대한 자세한 디렉토리 목록을 표시합니다.

[listing]
----
stat -c '%n %s bytes' /mount/path/directory
ls -ld /mount/path/directory
----
 `du`을 이 용도로 사용하지 마십시오.  `du`는 디렉토리 하위의 데이터에 접근 가능한 정보를 보고하는 반면,  `maxdir-size`는 디렉토리 메타데이터 파일 자체에 적용됩니다.

마운트 지점 아래에서 가장 큰 디렉터리를 찾으려면 크기별로 리프 디렉터리를 나열하고 Snapshot 복사본을 제거하는 `find` 명령을 실행하십시오. 다음은 가장 큰 디렉터리 10개를 반환합니다.

[listing]
----
find /mountpoint -name .snapshot -prune -o -type d -ls -links 2 -prune | sort -rn -k 7 | head
----
일곱 번째 열은 디렉터리 파일 크기를 바이트 단위로 나타냅니다. 기본값인 320MB 디렉터리는 335,544,320바이트로 표시됩니다. 이 기능은 수백만 개의 파일이 있는 디렉터리에서도 빠르게 실행됩니다.



[[view-directory-size-from-an-smb-client]]
== SMB 클라이언트에서 디렉토리 크기 보기

Windows 및 SMB 클라이언트는 디렉토리 자체의 메타데이터 크기를 노출하지 않으므로  `maxdir-size`에 대한  `stat` 또는  `ls -ld`의 직접적인 SMB 대응 항목이 없습니다:

* `dir`디렉토리를  `<DIR>`자체 크기 없이 나열합니다.
* 파일 탐색기의 폴더 *속성* 대화 상자에는 폴더 아래에 포함된 데이터의 총 크기( `du`에 해당)가 표시되며, 디렉터리 메타데이터 파일의 크기는 표시되지 않습니다.


SMB에서 제공하는 데이터 세트의 디렉토리 크기를 측정하려면 다음 방법 중 하나를 사용하십시오.

* 해당 볼륨이 NFS도 지원하는 경우, 마운트한 후  `stat`,  `ls -ld`, 또는  `find` 위의 방법을 사용하십시오.
* NetApp XCP를 사용하면 SMB 공유를 직접 스캔할 수 있습니다(다음 섹션 참조).




[[scan-directory-sizes-with-xcp]]
== XCP를 사용하여 디렉토리 크기 스캔

NetApp XCP는 파일 시스템을 병렬로 스캔하여 디렉터리 크기와 개수를 보고하므로 대규모 데이터 세트 또는 FlexGroup 데이터 세트에 유용합니다. NFS 내보내기 및 SMB 공유 모두에서 작동합니다. XCP는 일치 항목을 반환하기 전에 전체 파일 시스템을 스캔하므로 파일 수가 많은 데이터 세트의 경우 시간이 다소 소요될 수 있습니다.


NOTE: XCP 1.5는 툴을  `scan` 및  `diag` 등의 하위 명령어로 재구성했습니다. XCP 1.5 이상 버전에서는  `xcp scan` 형식을 사용하십시오. 이전 릴리스에서는  `scan` 동사 없이 동일한  `-match` 및  `-fmt` 옵션을 직접 실행하십시오(예:  `xcp -match "type == d" -fmt "..." <host>:/<export>`).

가장 큰 디렉토리의 항목 수( `Dirsize`로 표시됨)와 파일 및 디렉토리 개수를 포함하는 트리 통계 보고서를 출력합니다.

[listing]
----
xcp scan -stats <host>:/<export>
----
각 디렉토리와 해당 디렉토리 파일 크기를 바이트 단위로 나열합니다(가장 큰 파일부터). 디렉토리 오브젝트의 `used` 값은 디렉토리 메타데이터 크기를 나타내며 `maxdir-size` 상한값입니다.

[listing]
----
xcp scan -match "type == d" -fmt "'{} {}'.format(used, x)" <host>:/<export> | sort -rn
----
콘솔에 표시되는 간략한 합계 대신 정확한 값의 보고서를 저장하려면  `-csv` 또는  `-html`을(를) 추가하십시오.

선택한 항목 수보다 많은 디렉토리로 스캔 범위를 제한하려면  `xcp diag find`를 사용하십시오. 다음 예는 항목이 2,000개 이상인 디렉토리를 나열합니다(link:https://www.netapp.com/pdf.html?item=/media/12385-tr4571.pdf["TR-4571: NetApp ONTAP FlexGroup 볼륨"^]에서 발췌).

[listing]
----
xcp diag find --branch-match True -fmt "'{size} {name}'.format(size=x.digest, name=x)" <host>:/<export> 2>/dev/null | awk '{if ($1 > 2000) print $1 " " $2}'
----


[[locate-a-directory-reported-by-ems]]
== EMS에서 보고한 디렉토리 찾기

maxdir-size EMS 이벤트에는 볼륨 및 파일 ID가 포함되어 있습니다. 다음 명령을 사용하여 해당 inode를 경로로 변환하십시오.

[listing]
----
volume file show-inode -vserver <svm> -volume <volume-or-constituent> -inode-number <file-id>
----
보고된 파일 ID는 파일 생성이 실패한 파일이 아니라, 용량 제한에 도달했거나 근접한 디렉터리의 파일 ID입니다.


NOTE: FlexGroup의 경우, `volume file show-inode`는 FlexGroup 이름 대신 구성 요소를 기준으로 작동합니다. EMS 이벤트에서 지정한 구성 요소 이름(예: `fg__0024` 등)을 사용하십시오.
