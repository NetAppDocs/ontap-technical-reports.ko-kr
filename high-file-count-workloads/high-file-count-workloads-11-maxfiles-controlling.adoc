= maxfiles 제어
:allow-uri-read: 
:icons: font
:imagesdir: ../media/high-file-count-workloads/


[role="lead"]
볼륨  `-files` 옵션은 공용 inode 상한입니다. 워크로드가 inode를 모두 소진하기 전에 계획된 값 또는 현재 `files-maximum-possible` 값으로 이 값을 높이십시오. 제한 사항, NFS 파일 ID 동작 및 소진 증상은 link:high-file-count-workloads-10-maxfiles-limits.html["Maxfiles 및 ONTAP inode 정보"]에 설명되어 있습니다.



[[set-a-specific-ceiling]]
== 특정 상한선 설정

용량 계획에 특정 값이 필요할 때 `volume modify -files` 사용하십시오.

[listing]
----
volume modify -vserver <svm> -volume <volume> -files <inode-count>
----
ONTAP는 요청된 값을 볼륨 크기, 최대 가능 값 및 이미 할당된 inode 파일 용량과 비교하여 유효성을 검사합니다. 구성된 최대값은 이미 도달한 inode 파일 용량보다 낮출 수 없습니다.

FlexGroup의 경우 FlexGroup 이름과 원하는 FlexGroup 전체 합계를 지정하십시오. 구성원별로 `files` 독립적으로 설정하지 마십시오. ONTAP는 요청된 합계를 현재 구성원들에게 균등하게 분배하며, 각 구성원은 자신의 몫을 이행합니다.

[listing]
----
volume modify -vserver <svm> -volume <flexgroup> -files <flexgroup-total-inodes>
----
값을 변경한 후에는 구성 요소 수준의  `files` 및  `files-used`을 검사하십시오. 사용량이 구성된 제한만큼 균등하게 분배되지 않을 수 있기 때문입니다.

[listing]
----
volume show -vserver <svm> -volume-style-extended flexgroup-constituent -fields files,files-used
----
일부 ONTAP 명령은 상대적 증가를 허용합니다.

[listing]
----
volume modify -vserver <svm> -volume <volume> -files +<additional-inodes>
----
결과를  `volume show`로 확인하세요.



[[setting-files-to-the-maximum-up-front]]
== 파일을 처음부터 최대로 설정합니다.

 `files`를 현재  `files-maximum-possible`로 상향 조정해도 공용 inode 파일이 미리 할당되거나 해당 inode 레코드 용량이 예약되지는 않습니다. 따라서 즉각적인 공간 부족 위험은 낮습니다. 파일 수가 많은 NAS 볼륨의 경우, inode 부족 이벤트가 발생하기를 기다리지 말고 볼륨 크기 및 프로토콜 제약 조건이 허용하는 한  `files`를 볼륨이 수용할 수 있는 최대 값으로 설정하십시오.

나머지 고려 사항은 네임스페이스가 실제로 해당 한계까지 커질 경우 발생하는 상황과 더 이상 높일 수 없는 한계에 도달할 경우에 관한 것입니다.

* *용량은 inode가 할당될 때만 소모됩니다.* 각 ONTAP 9 공용 inode는 inode 파일에서 288바이트를 사용하며, inode 파일 구조 및 기타 메타데이터도 포함됩니다. FlexVol 최대 용량에 도달하면 원시 inode 레코드만 해도 약 2,040,109,451 × 288바이트(약 547GiB)에 달합니다. 사용된 공간은 기본 스토리지도 차지하므로 볼륨 사용률뿐만 아니라 전체 여유 공간도 모니터링해야 합니다. link:high-file-count-workloads-08-maxfiles-high-file-counts.html#capacity-impact["용량 영향"]을 참조하십시오.
* *inode 파일이 커진 후에는  `files`를  `inodefile-public-capacity` 아래로 낮출 수 없습니다.* 상한값을 높게 설정해도 사용되지 않는 용량은 잠기지 않으며, 할당된 레코드가 잠깁니다.
* *FlexVol에서 2,040,109,451은 하드 스톱입니다.* 해당 볼륨에는 더 이상 공용 inode를 추가할 수 없습니다. 워크로드가 하나의 볼륨의 절대적인 최대 크기를 초과할 가능성이 있는 경우, 구성 요소를 추가할 수 있도록 FlexGroup을 사용하십시오. FlexVol 또는 구성 요소를 *현재 크기*에서 허용하는 최대 크기로 설정하는 것이 여전히 적절하며, 이 값은 일반적으로 2,040,109,451보다 훨씬 작습니다.
* *FlexGroup 전체의 inode 총 개수는 20억 개를 초과할 수 있습니다.* (통합 ONTAP에서는 최대 4,000억 개, ONTAP 9.19.1 이상을 실행하는 AFX에서는 최대 1조 개). NFS의 경우, 파일 ID 개수가 20억 개에 가까워지기 전에 64비트 파일 식별자를 활성화하십시오. 자세한 내용은 link:high-file-count-workloads-10-maxfiles-limits.html#nfs-64-bit-file-identifiers-and-flexgroup-file-counts["NFS 64비트 파일 식별자 및 FlexGroup 파일 개수"]을 참조하십시오.
* *계속해서 모니터링하세요 `files-used` against `files`.* 최대 설정값을 사용하면 기본 상한값이 예상치 못한 문제로 발생하는 것을 방지할 수 있지만, 지원되는 최대값에 도달하면 볼륨에 필요한 inode가 부족해질 수 있습니다.


현재 최대값을 적용하려면 ONTAP 9.9.1부터 시작하는 고급 `files-set-maximum` 작업을 사용하십시오.

[listing]
----
set -privilege advanced
volume modify -vserver <svm> -volume <volume> -files-set-maximum true
----
이는 일회성 작업이며 영구적인 할당 모드가 아닙니다.  `true`만 유효합니다. 볼륨 크기가 나중에 증가하면 새 최대값을 적용해야 하는 경우 다시 실행하십시오. 최대값보다 작은 값을 의도적으로 설정하려는 경우  `-files`를 사용하십시오. FlexVol 볼륨(또는 FlexGroup 구성 요소)이 약 7.8TB 이상인 경우 설정할 수 있는 최대값은 절대값인 2,040,109,451이며, 이 값은 볼륨 크기가 증가해도 더 이상 증가하지 않습니다.
