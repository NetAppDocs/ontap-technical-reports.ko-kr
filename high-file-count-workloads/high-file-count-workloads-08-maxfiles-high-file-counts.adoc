= ONTAP의 높은 파일 수 및 inode 용량
:allow-uri-read: 
:icons: font
:imagesdir: ../media/high-file-count-workloads/


[role="lead"]
ONTAP는 구성된 공용 inode 제한, 현재 공용 inode 사용량 및 할당된 공용 inode 파일의 최대 용량을 별도의 값으로 보고합니다.



[[high-file-counts-in-ontap]]
== ONTAP의 높은 파일 수

ONTAP는 inode를 사용하여 파일 시스템 오브젝트를 추적합니다. CLI, REST API 또는 System Manager에서 다음 볼륨 값을 사용하여 공용 inode 사용량을 모니터링할 수 있습니다.

* `files`은(는) 구성된 공용 inode 상한값입니다.
* `files-used` 현재 사용 중인 공용 inode의 개수입니다.


이  `files` 옵션은 공용 inode 파일에 할당할 수 있는 공용 inode 항목의 수를 제어합니다.  `files` 제한 값을 늘린다고 해서 즉시 액티브 파일 시스템에 inode 또는 inode 파일 공간이 할당되는 것은 아닙니다. 대신 볼륨에서 허용하는 상한값을 설정합니다.

파일, 디렉터리, ACL, 명명된 스트림 또는 공용 디렉터리 인덱스를 생성하면 공용 inode 파일의 크기가 증가할 수 있습니다. 오브젝트를 삭제하면 `files-used` 공용 inode가 줄어들고 재사용을 위해 반환되지만, 공용 inode 파일의 크기가 줄어들지는 않습니다.

파일 개수 사용량 세부 정보를 보는 방법의 예는 link:high-file-count-workloads-12-maxfiles-monitoring.html#monitoring-example["모니터링 예시"]을 참조하십시오. 사이징 지침은 link:high-file-count-workloads-14-best-practices.html["파일 수가 많은 NAS 워크로드 최적 사례"]을 참조하십시오.



[[how-an-inode-count-increments]]
== inode 카운트가 증가하는 방법

모든 inode가 공용 inode 제한에 포함되는 것은 아닙니다. link:high-file-count-workloads-09-maxfiles.html#private-inodes["프라이빗 inode"]는 포함되지 않습니다. 파일, 디렉터리, ACL, 명명된 스트림 및 공용 디렉터리 인덱스 등 link:high-file-count-workloads-09-maxfiles.html#public-inodes["공용 이노드"]는 포함됩니다.

 `files-used`은 공용 inode가 사용되기 시작하면 증가합니다. 할당된 inode 파일에 사용 가능한 공용 inode가 이미 있는 경우  `files-used`은 여전히 증가하지만  `inodefile-public-capacity`은 증가하지 않습니다. 사용 가능한 공용 inode가 더 이상 없으면 ONTAP은 공용 inode 파일을 최대  `files`까지 확장하고 두 값 모두 증가합니다.

일반적인 작업에는 다음이 포함됩니다.

* 파일, 디렉터리, 심볼 링크 또는 특수 파일 생성: 상위 디렉터리에 공용 inode +1개와 새 이름이 추가됩니다.
* 하드 링크 생성: 상위 디렉터리에 공용 inode +0개 및 이름 +1개.
* 이미 ACL inode가 없는 오브젝트에 NTFS 또는 NFSv4 ACL을 저장하는 경우: ACL 공유에 따라 최대 +1개의 공용 inode를 사용할 수 있습니다.
* 명명된 스트림 생성: 스트림에 대한 공용 inode가 하나 추가되고, 필요한 경우 스트림 디렉터리 inode도 추가됩니다. 둘 다 상위 사용자 디렉터리에 이름을 추가하지는 않습니다.
* 디렉터리 인덱스를 공용 공간으로 이동: 인덱싱된 디렉터리당 약 1개의 공용 inode가 추가됩니다.


오브젝트 유형, ACL 공유 및 스트림 등 `Zone.Identifier`이 표시되는 파일 수에 미치는 영향에 대한 설명은 link:high-file-count-workloads-09-maxfiles.html["ONTAP inode 유형"]을 참조하십시오.

`files-used`공용 inode가 사용 가능해지면(예: 삭제가 완료되고 오브젝트가 더 이상 좀비로 유지되지 않는 경우) 감소합니다. `inodefile-public-capacity`는 최고 수위 표시에 유지되며 inode 파일 크기는 절대 감소하지 않습니다.

New는 할당된 inode 파일이 가득 찰 때까지 재사용 없는 레코드를 생성하며, 그 후 `files` 및 볼륨 용량이 허용하는 경우 ONTAP가 해당 파일을 확장합니다.



[[how-high-file-counts-affect-nas-workloads]]
== 파일 수가 많을 경우 NAS 부하에 미치는 영향

파일 수가 많을수록 데이터 전송 대비 메타데이터 작업의 비율이 높아집니다. 일반적인 작업은 다음과 같습니다.

* inode 할당 및 해제
* 디렉토리 이름과 파일 핸들 조회
* 속성, 권한 및 타임스탬프 읽기 및 업데이트
* 파일 열기, 닫기, 이름 변경, 연결 및 삭제
* 디렉토리 열거 및 디렉토리 트리 탐색
* 분석, 백업, 복제 또는 보안 기능을 위해 네임스페이스 스캔


성능에 미치는 영향은 작업 속도, 동시성, 프로토콜 동작, 네임스페이스 레이아웃, 캐시 상태 및 노드 리소스에 따라 달라집니다. 파일 총 개수만으로는 성능을 예측할 수 없습니다. 수백만 개의 파일이 여러 활성 디렉터리에 분산되어 있는 경우, 동일한 파일 수가 단일 디렉터리 공간에 집중되어 있는 경우보다 더 많은 병렬 처리가 가능할 수 있습니다.



[[capacity-impact]]
== 용량 영향

ONTAP 9의 각 inode는 inode 파일에서 288바이트를 차지합니다. 대략적인 계획 수립 크기는 다음과 같습니다.

[listing]
----
inode-file bytes = inode count × 288
----
|===
| 이노드 | 대략적인 원시 inode 바이트 | 근사 이진 용량 


| 100만 | 288,000,000 | 274.7 MiB 


| 1억 | 28,800,000,000 | 26.8 GiB 


| 10억 | 288,000,000,000 | 268.2 GiB 
|===
이 수치는 inode 레코드를 설명합니다. 관찰된 물리적 사용량에는 inode 파일 구조, 블록 반올림, 스냅샷 보존 기간 및 기타 메타데이터도 포함될 수 있습니다.

 `files`을(를) 늘리면 허용되는 상한선이 변경되지만, 해당하는 모든 inode 파일 공간이 즉시 할당되지는 않습니다. inode 파일이 커짐에 따라 용량이 소비됩니다. 나중에 100만 개의 공용 inode를 보유하게 되면, 원시 inode 레코드는 실제 볼륨 용량의 288MB(약 274.7MiB)를 사용합니다. inode 파일은 축소되지 않으므로 용량 계획 시 역사적 최고 할당량을 고려해야 합니다. 나중에  `files`을(를) 낮출 수 있지만,  `inodefile-public-capacity` 미만으로 낮출 수는 없습니다. 해당 필드는 이전  `files` 설정이나 피크  `files-used`이(가) 아니라 할당된 inode 파일의 최고 기록 마크입니다. 예를 들어, inode 파일이 이미 100만 개의 레코드로 증가한 경우 현재  `files-used`이(가) 훨씬 낮더라도  `files`을(를) 100만 미만으로 설정할 수 없습니다. inode 파일을 그만큼 늘리지 않고  `files`을(를) 늘린 경우, 현재 용량까지 다시 낮출 수 있습니다.

inode 파일에 사용된 물리적 용량은  `maxdir-size` 사용된 용량과 별개입니다.  `maxdir-size`은 각 디렉토리의 이름 매핑 파일의 바이트 크기를 제한합니다. 320MB 디렉토리 파일은 해당 디렉토리에서 320MB의 디렉토리 파일 블록을 사용하며, 유사한 크기의 inode 파일은 볼륨 전체의 inode 채우기를 나타내며  `maxdir-size`에 의해 제한되지 않습니다.

inode 파일 공간을 용량 단위로 검사하는 방법과  `inodefile-public-capacity`을 inode 개수로 읽는 방법에 대해서는 link:high-file-count-workloads-12-maxfiles-monitoring.html#monitoring-example["최대 파일, EMS 이벤트 및 ONTAP 개선 사항을 모니터링합니다."]을 참조하십시오.
