= 최대 파일, EMS 이벤트 및 ONTAP 개선 사항을 모니터링합니다.
:allow-uri-read: 
:icons: font
:imagesdir: ../media/high-file-count-workloads/


[role="lead"]
공용 inode의 현재 사용량과 공용 inode 파일에 할당된 최대 용량을 모두 모니터링합니다. EMS 이벤트를 사용하여 용량 고갈 및 구성 요소 불균형을 감지합니다.



[[ems-messages-related-to-maxfiles]]
== maxfiles 관련 EMS 메시지



[[callhome-no-inodes]]
=== `callhome.no.inodes`

이 오류 이벤트는 볼륨에 inode가 부족함을 나타냅니다. inode를 사용할 수 있게 되거나 구성된 최대값이 증가될 때까지 새 파일 시스템 객체를 생성할 수 없습니다. 제한을 변경하기 전에  `files`,  `files-used`,  `files-maximum-possible`, 볼륨 용량을 확인하십시오.



[[flexgroup-constituent-events]]
=== FlexGroup 구성 요소 이벤트

* `fg.inodes.member.nearlyFull`이는 해당 구성 요소의 inode가 거의 소진되었음을 나타냅니다. ONTAP은 해당 구성 요소에 대한 생성 횟수를 줄여 배포 및 성능에 영향을 미칠 수 있습니다.
* `fg.inodes.member.full` 구성 요소의 inode가 부족하여 새 파일을 수락할 수 없음을 나타냅니다.
* `fg.inodes.member.allOK` 이는 거의 가득 참 또는 가득 참 이벤트를 발생시킨 조건이 더 이상 적용되지 않음을 나타냅니다.


FlexGroup 이벤트의 경우, 구성원 분포뿐 아니라 FlexGroup 수준의 총계도 조사하십시오. FlexGroup 파일 허용량을 늘리십시오. 개별 구성원에 `files` 직접 설정하려고 시도하는 대신 FlexGroup 파일 허용량을 늘리십시오. 데이터 용량이 부족한 구성원은 전체 FlexGroup 보고서에 `ENOSPC` 영향을 미칠 수 있으며 심지어 실패할 수도 `ls` 있습니다. link:high-file-count-workloads-10-maxfiles-limits.html#flexgroup-constituent-out-of-space["FlexGroup 구성 요소 공간 부족"]를 참조하십시오.



[[monitoring-example]]
== 모니터링 예시

CLI를 사용하여 공개 사용량 상한선과 현재 사용량을 확인합니다.

[listing]
----
volume show -vserver <svm> -volume <volume> -fields files,files-used
----
고급 권한 설정 시, 가능한 최대값과 할당된 공용 inode 파일 용량을 포함하십시오.

[listing]
----
set -privilege advanced
volume show -vserver <svm> -volume <volume> -fields files,files-used,files-maximum-possible,files-set-maximum,inodefile-public-capacity

volume show-space -vserver <svm> -volume <volume>
----
REST API를 사용하여 공개 `files` 상한선과 현재 사용량을 조회합니다.

[listing]
----
GET /api/storage/volumes?name=<volume>&fields=files
----
REST  `files.maximum`및  `files.used`필드는 CLI  `files`및  `files-used`에 해당합니다.  `inodefile-public-capacity`에 고급 CLI 필드를 사용하십시오.

`files-used`에는 공용 ACL inode, 명명된 스트림, 스트림 디렉터리, 공용 디렉터리 인덱스 및 기타 공용 객체가 포함됩니다.  `volume show`는 별도의 ACL inode 카운터를 제공하지 않습니다.

현재 사용량과 inode 파일 용량을 모두 추적하십시오. 대량 삭제 후 낮은 `files-used` 값이 나왔다고 해서 inode 파일 용량이 반환된 것은 아닙니다.



[[ontap-functionality-and-enhancements-related-to-maxfiles]]
== ONTAP maxfiles 관련 기능 및 개선 사항

|===
| ONTAP 릴리스 | 기능 


| 이전 ONTAP 9 릴리스 | 관리자는  `files` 및  `files-used`을(를) 확인하고 특정  `-files` 값을 설정할 수 있습니다. 기본 자동 값은 볼륨 크기가 약 680GB에 도달했을 때 21,251,126에서 증가가 멈췄습니다. 이는 기본 크기 조정 한계값이며 구성 가능한 최대값이 아닙니다. 


| ONTAP 9.9.1 | 추가된 `-files-set-maximum true`은(는)  `files`을(를) 현재 `files-maximum-possible`(으)로 설정하는 일회성 작업입니다. link:high-file-count-workloads-11-maxfiles-controlling.html#setting-files-to-the-maximum-up-front["파일을 처음부터 최대로 설정합니다."]을 참조하십시오. 


| ONTAP 9.13.1 | 볼륨 크기가 초기 약 2,100만 단위를 넘어 증가함에 따라 자동 기본 inode 크기 조정이 계속됩니다. 


| ONTAP 9.17.1 | 디렉터리 인덱스 inode를 공용 inode 공간으로 배치하고 마이그레이션하는 옵션이 추가되었습니다. link:high-file-count-workloads-04-maxdirsize-indexing.html#about-private-and-public-index-inodes["개인 및 공용 인덱스 inode에 대하여"]을 참조하십시오. 
|===
릴리스 지원 및 제한 사항은 플랫폼 및 볼륨 유형에 따라 다를 수 있습니다. 사용 중인 ONTAP 릴리스에 대한 명령 참조에서 동작을 확인하십시오.
